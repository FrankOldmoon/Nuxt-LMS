# Skill: Build the course chapter tree (orders)

> Purpose: build a **nested chapter tree** for a course. The tree is stored in
> `courses.orders` (a JSON array); **group nodes in the tree are real chapters too**
> (same `chapters` table), and nesting is formed via `parentId` pointing at the parent
> chapter id (consistent with the live course: group chapters may contain intro content).
>
> Reference: the `orders` returned by `GET /api/courses/show?id=<id>` (same shape as existing courses).

## Tree conventions (important)

- **Every tree entry maps to a chapter** (`id` is the chapter id as a string); a group title = a chapter with `parentId=null`, children point at it via `parentId`
- `label` is the display name; **do not include numbering** (write "Headings and Paragraphs", not "1.1 Headings and Paragraphs") — the sidebar adds `1 / 1.1 / 1.1.1` automatically
- Maximum 3 levels: top-level chapter → sub-chapter → grand-child chapter (nested via parentId)
- (Front-end extras, not standard usage: `id='course'` renders a course-home link and `id='custom-xxx'` renders a `#anchor` placeholder; standard trees should use chapter ids only)

## Two steps

### Step 1: create the chapters in batch

`POST /api/chapters/add` (admin or the course teacher)

```json
{
  "name": "Chapter title",
  "courseId": 1,
  "isOpen": true
}
```

- `name` is required; `courseId` is required; `isOpen` defaults to the course's `lmsConfig.course.defaultChapterOpen` when omitted
- Success response: `data` is an array; take `data[0].id` as the chapter id
- **Group chapters** are created the same way as normal chapters (the name is the group name, e.g. "Basic Syntax") and become parent nodes later
- Batch = loop over the calls and collect each `id`

### Step 2: set the course tree (orders)

`POST /api/courses/update`, body:

```json
{
  "id": 1,
  "orders": [
    { "id": "74", "label": "Basic Syntax", "parentId": null, "order": 0 },
    { "id": "66", "label": "Headings and Paragraphs", "parentId": "74", "order": 0 },
    { "id": "67", "label": "Emphasis and Lists", "parentId": "74", "order": 1 },
    { "id": "68", "label": "Links and Images", "parentId": "74", "order": 2 },
    { "id": "75", "label": "Advanced Syntax", "parentId": null, "order": 1 },
    { "id": "69", "label": "Code", "parentId": "75", "order": 0 },
    { "id": "70", "label": "Tables and Quotes", "parentId": "75", "order": 1 },
    { "id": "71", "label": "Math Formulas", "parentId": "75", "order": 2 },
    { "id": "76", "label": "Practice", "parentId": null, "order": 2 },
    { "id": "72", "label": "Guided Practice I", "parentId": "76", "order": 0 },
    { "id": "73", "label": "Guided Practice II", "parentId": "76", "order": 1 }
  ]
}
```

### orders entry fields

| Field | Description |
| --- | --- |
| `id` | Chapter id as a **string** (e.g. `"74"`) |
| `label` | Display title (no numbering). Written back to `chapters.name` on update |
| `parentId` | Parent chapter `id`; `null` for top-level entries |
| `order` | Sibling sort order (number, ascending) |

### Nesting rules (matches useNavigation / useCourseDetailPage on the front end)

- `parentId === null` entries are top-level chapters
- `parentId === <some chapter id>` entries are its children, recursively up to 3 levels (top level included)
- Rendering order: top-level sorted by `order`, children sorted by `order`; the `1 / 1.1 / 1.1.1` numbering is generated by the front end

## Notes

- Permission: `requireCourseTeacher` (admin or a teacher of the course)
- Create chapters first to get ids, then write orders; `orders` must not reference non-existent chapter ids
- Group chapters (parent nodes) should have intro content as well; questions are optional (follow the live courses)
- Updating orders broadcasts `home-changed` to refresh the home navigation; name sync happens in `courses/update.post.ts`
- The actual learning page path of a chapter: `/course/<courseId>/<chapterId>`
